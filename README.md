1. 회사 메일로 가입 → **인증메일 링크**를 눌러야 들어온다.

### 완료 처리

| | 기한이 지나면 |
|---|---|
| **팀 공통 업무** | 저절로 완료 |
| **담당자 업무** | 다음 날 **「놓친 업무 확인」** 창이 뜬다 |

창은 두 묶음이다 — 위 **놓친 업무**(날짜가 지난 미완료), 아래 **보류 업무**(보류함 전체). 줄마다 아이콘 셋: **✓ 완료** · **⇥ 오늘로 이동** · **📅 날짜 변경**(고르는 즉시 그 날로).
⚠ 창을 닫으면 손대지 않은 놓친 업무는 **보류함으로 넘어간다.** 보류 업무는 날짜를 다시 잡거나 완료할 때까지 매일 다시 보인다. 보류 업무를 완료하면 원래 날짜로 완료된다.

### 보류한 업무

넘긴 업무가 모이는 곳. 일자 패널 아래에 있다.

- **내 업무만 보기**로 좁힌다.
- **달력 날짜로 끌어다 놓으면** 그 날짜로 되살아난다.

### 반복 업무

매주 · 격주 · 매월 · 매년. 회차별로 완료를 표시하고, 회차 하나만 옮기거나 뺄 수 있다.

- 매월 반복은 **시작일의 날짜**를 따른다 → 14일·28일처럼 두 번이면 업무를 두 개로 만든다.
- ⚠ 업무 현황·위젯의 날짜는 **지금 볼 회차**다. 지난 회차가 안 끝났으면 그 날짜(지연).

### 우클릭

| 우클릭한 곳 | 할 수 있는 일 |
|---|---|
| 달력 날짜 | 업무 추가 · **휴무일 지정/해제**(관리자) |
| 업무 카드 | 완료 ↔ 진행 · 수정 · 제목 복사 · 삭제 |

**단체연차**는 날짜 우클릭 > 휴무일로 지정. 공휴일과 같은 색으로 칠해진다.

### 찾기

맨 위 오른쪽 검색창(또는 `Ctrl+K`)에 바로 입력. **업무 · 현장 · 하자**를 한 번에 찾는다.

### 알아 둘 것

- 오후 5시 이후 접속하면 **「오늘 남은 업무 N건」** 말풍선이 하루 한 번.
- 완료 6개월이 지나면 **보관함으로** 옮긴다. 지워지지 않고, 그 시기로 넘기거나 검색하면 보인다.

### 주간 업무

> 보고 주기는 **목요일 시작, 수요일 종료**. (8/13 ~ 8/19 → 8/20 ~ 8/26)

## 4. 업무 도구

D+60 점검·사진대지·견적 검토·도면 인쇄·재하자 추적·생산성 검토 여섯 가지. D+60 점검만 팀이 함께 쓰는 기록이라 서버(RTDB `calapp/d60`)에 남고, 나머지 다섯은 **이 창 메모리에서만 돈다** — 올린 사진·산출서·도면은 서버로 가지 않고, 창을 닫으면 사라진다. 결과물은 인쇄하거나 복사해서 가져간다.

### D+60 점검

준공 두 달 뒤 초기 품질 점검. 현장에서 폰으로 **체크**하고, 데스크톱에서 **한눈에 보고 엑셀로 낸다**. 사진·조치 기록은 없다(사진은 무료 요금제 용량, 조치는 사내 별도 보고서).

| 하는 일 | 방법 |
|---|---|
| 점검 대상 | 조직 관리에 **준공일**이 있는 현장이면 저절로 목록에 든다 — 점검일 = 준공일 + 2개월(연한 글씨). 목록의 점검일 칸을 눌러 실제 날짜로 고치면 진해진다 |
| 점검일 확정 | 첫 판정을 저장하는 순간 점검일이 그날로 확정된다. 예정일이 지났는데 손대지 않은 현장은 점검일이 붉게 표시된다. |
| 폰 | 목록의 현장 줄을 누르면 펼쳐진다 — 공종마다 한 줄(양호·지적·미확인 수, 그 공종의 점검일)이고 이름을 누르면 들어간다. 점검일은 공종마다 조금 다를 수 있어 따로 두며, 목록·데스크톱 표의 대표 점검일은 **건축**. 점검 화면 머리는 한 줄 「‹ 현장명 ····· 공종 점검일」. 세대는 밑줄 탭(고른 탭을 다시 누르면 동·호 고치기·삭제, 「+ 세대」). 항목은 모두 접혀 있고 눌러 펼쳐 판정하면 다시 접힌다. 다 본 공간 칩은 ✓, 지적이 있으면 빨간 점. **좌우로 밀면** 이전/다음 공간(옆 판이 손가락을 따라 미리 보인다), 마지막은 민원사항. |
| 조경 | 전유부(세대) 없음 — 공용부·민원사항만 |
| 민원사항 | 서식(공간·항목)이 있는 체크리스트 + 맨 뒤 **현장 접수**(현장에서 동·호·내용을 적어 넣는 건). 서식 화면에서 다른 구분처럼 공간·항목을 두며, 기본 공간은 미분양 세대 · 미분양 상가 · 입주자 예정 협의회 · 공동도급 · 기타. |
| 공종 칸 | 양호/지적/N/A 뒤의 「· n」은 아직 판정하지 않은 항목 수. 마우스를 올리면 풀어 보여 준다. 결과 칸에 올리면 누가·언제 판정했는지. |
| 표 복사 | 여러 줄을 끌어 잡고 Ctrl+C — 칸은 탭으로 나뉘어 엑셀에 그대로 붙는다. |
| 목록 | 왼쪽 열두 달 격자(그 달 점검 건수)로 해를 오가고, 고른 달의 줄에만 음영. 위 권역 탭, 표는 열 머리를 눌러 정렬, 대공종 칸은 양호/지적/N/A 수 |
| 대공종 | 건축 · 설비 · 전기 · 조경 — 각자 따로 점검한다. 상세의 위 탭(숫자는 지적 수) |
| 구분 | 전유부(세대) · 공용부 · 민원사항. 전유부는 왼쪽 「+ 세대」로 그날 들어간 세대를 넣는다(미리 정하지 않는다). 민원사항은 「+ 접수」로 동·호·내용 |
| 서식 | 왼쪽 위 전환 「서식」. 공종마다 전유부·공용부 **공간**(조직 관리 권역 줄과 같은 인라인 이름 고치기·삭제, 머리 「+」로 추가, 비었으면 「기본 공간 넣기」) → 공간마다 점검항목(공종 · 항목 · 조치사항 기본값). 위 「추가」와 줄의 연필·쓰레기통 |
| 서식 가져오기 · 내보내기 | 서식 화면 탭 오른쪽. **가져오기**는 `[{대공종,구분,공간,공종,점검사항,조치사항}, …]` 꼴 JSON 파일을 읽어 확인창(공종·구분별 새 공간·항목 수)을 거쳐 서식에 넣는다 — 앱에 자료를 싣지 않고 파일에서 바로 저장. 같은 공간 이름은 합치고 같은 공간의 같은 점검사항은 건너뛰어 여러 번 넣어도 두 배가 되지 않는다. **내보내기**는 지금 서식을 같은 꼴 JSON 으로. 넣은 뒤에는 서식 화면에서 여느 항목처럼 고친다. |
| 체크(폰) | 현장 → 공종 → 구분 → 세대 · 공간 칩 → 항목마다 **양호 · 지적 · N/A** 큰 단추(46px). 지적이면 조치사항 칸이 열리고 서식 기본값이 들어 있다 — 고치면 **그 현장에만** 저장되고 서식은 그대로 |
| 정리(데스크톱) | 표의 결과 칸을 눌러 판정을 바꾸고, 조치사항 칸을 눌러 바로 고친다. 표시 세그(전체 · 양호 · 지적 · N/A · 미확인)로 거른다 — 미확인이 현장에서 빠뜨린 항목 |
| 엑셀 | 머리줄 「엑셀」 — 목록에서는 그 해 현장별 공종 집계, 상세에서는 공종별 시트에 세대·공간·항목·결과·조치사항 |


### 사진대지 작성

|---|---|
| 사진 넣기 | **사진** 또는 **폴더**(하위 폴더까지 읽는다) |

### 견적 검토

업체 산출서의 **산출 근거 열**을 엑셀에서 복사해 붙여넣으면 줄마다 계산식을 검산한다.

| 하는 일 | 방법 |
|---|---|
| 읽는 규칙 | 「1. 공용욕실」의 번호가 **1 로 되돌아가면 다음 세대** · 「- 항목」 + 「 : 식=수량단위」 · 식과 `= 11.1m` 가 두 줄로 나뉘어도 이어 읽는다 |
| 한 줄로 붙여넣어도 | 엑셀이 줄바꿈을 지워 한 줄로 들어와도 표시 앞에서 끊어 읽는다 |
| 판정 | 정답 · 오답(계산값·차이를 사유에 적는다) · 제외 |
| 기준 | 반올림 정수 / 0.0(기본) / 0.00 / 안 함 · 허용 오차 없음 / ±0.1 / ±0.5 |
| 세대 합계 | 세대마다 **항목별**로 더해 정수로 올린다. 조공·다기능공은 올리지 않는다. 수량이 없는 항목(해체/설치)은 1식으로 센다 |
| 업체가 적은 「* 합계」 | 따로 표시하고 우리 합계와 **견주기만** 한다(다르면 ⚠) |
| 보기 | 전체 · 정답 · 오답 · 제외 · **합계**(세대 합계 줄만) |
| 가져가기 | 칸을 끌어 고르고 Ctrl+C(엑셀식) · 우클릭으로 이 줄 / 오답만 / 전체 / 판정·사유 복사 |
- (903차) 식 앞에 「AC :」 같은 라벨이 붙어도 읽고(라벨은 항목 이름에 붙는다), 「1:3=4:X」 + 다음 줄 「X=12」 비례식은 X 를 풀어 적힌 값과 견준다(X 자리는 넷 중 어디든, 「=> 17500 : 15000 = 6.7 : X」 꼴도, X 값이 없으면 제외). 괄호 안 라벨 「-(AC : 1.4*0.5)」·「①(0.4*0.3)+②(1.1*0.3)」 번호도 걷어 읽고, 항목 아래 「① 0.8m」 「② 2.5+0.9=5.5m」 번호 줄은 줄마다, 「합계 : 0.8+5.5+0.8=7.1m」 「* 세대 균열 보수 합계 : …」 식이 붙은 합계 줄은 합계 무리에서 검토한다. 「* 일반줄눈 감액」처럼 합계가 아닌 별표 줄은 항목이다. 「[ 세대 합계 ]」 다음 줄의 「 : 6.8+3.3=10.1m」 도 합계로 검토한다.

### 폰 화면 — 하단 탭 (902차)
폰(≤960px)은 화면 아래 **하단 탭** 다섯 칸 — 메뉴 · 캘린더 · 업무 현황 · 업무 도구 · 하자처리 현황 — 으로 움직인다. 첫 칸 **메뉴**(햄버거)는 화면이 아니라 사이드바 드로어를 열고, 왼쪽 위 **프로필 원**은 계정·프로필을 연다. 업무 도구 칸은 바로 가지 않고, 아래에서 올라오는 시트에서 다섯 도구 중 하나를 고른다(시트가 떠 있어도 하단 탭은 그 위에 남아 바로 다른 화면으로 갈 수 있다). 주간/현장별은 업무 현황 화면 위의 전환 탭으로 고르고, 상단바가 달력처럼 「2026. 9. 4주차 ˅」(누르면 월 그림) · 보류 · 필터가 되며(찾기는 오른쪽 전역 찾기 하나), 완료·예정이 카드 둘로 나뉜다. 목록을 좌우로 밀면 탭이 아니라 **주(주간)·달(현장별)** 이 넘어가며, 앞뒤 주기가 손가락을 따라 미리 보인다(달력과 같다). 하자처리 현황 탭은 업무 도구와 같은 결 — 칸을 누르면 **현장 선택 시트**(팀 전체 대시보드 · 권역별 현장)가 먼저 뜨고, 고른 곳으로 간다. 화면 안에서는 맨 위 KPI 카드(꺽쇠)로도 같은 시트를 연다. 큰 달력은 5주를 기본으로 세로를 채우고 6주가 걸리는 달만 6등분한다. 점 달력에서 업무 패널을 좌우로 밀면 옆 날 업무가 손가락을 따라 미리 나오고, 놓으면 그날로 넘어간다. 달력에서 **날짜 칸을 눌러** 날이 바뀔 때도 같은 방향으로 미끄러진다. 조직·설정·팀 선택은 드로어(하단 탭 「메뉴」)에서 간다. 조직 관리의 현장 지도는 폰에서 두 손가락으로 확대·축소하고 한 손가락으로 옮긴다.

### 재하자 추적 · 생산성 검토 (901차)
둘 다 「전체 하자 목록」 한 파일(xlsx·csv)을 왼쪽 「하자 목록」 카드에서 열어 나눠 쓴다. 사내 엑셀은 AIP 보안 탓에 브라우저가 못 열므로 **CSV 로 저장해 올린다**(엑셀의 「CSV(쉼표로 분리)」 그대로, CP949 도 읽는다). 하자구분 열이 있으면 「세대」만 집계한다.
- **재하자 추적**: 같은 동·호·공간·공종에서 **완료 후(처리확인일 뒤)** 다시 접수된 건을 묶어 보여 준다. 하자유형이 달라도 후보로 올리고 「유형 다름」 배지로 표시(기준 「같음」이면 뺀다). 보수주체 전체/외주/시공업체 · 오른쪽 전체/확정/미확정/미처리. 보고 재하자가 맞으면 체크(현장별로 이 브라우저에 남는다). 머리줄 「엑셀」로 후보 목록을 내보낸다.
- **생산성 검토**: 보수주체 **외주** 건만 — 보수업체·시작·종료·공수/일(품의 기준)을 넣으면 총 처리 건수·총 투입일·총 투입 공수와 처리/일·건/공수·공수/건을 낸다. 투입일은 업체처리일(없으면 처리확인일). 일별(날짜 아래 건별 동·호·공종·접수내용·처리내용)·공종별·주차별. 「엑셀」은 실적 요약 + 처리 건 두 시트.
- 표 열 머리를 우클릭하면 「필터행 표시」 — 업무 목록과 같은 글자 포함 필터.

## 5. 하자처리 현황

하자 데이터의 **업로드·집계·게시·조회·처리계획 관리**를 이 앱에서 모두 수행한다. 관리자는 설정에서 HCS 원본 파일을 등록하고 [등록]으로 게시하며, 일반 사용자는 게시된 최신 현황을 조회한다.

| 화면 | 내용 |
|---|---|
| 하자 현황 | 팀 전체 합계 |
| 권역 > 현장 | 접수 · 처리 · 미처리 · 장기미처리 |

- 맨 위에 **기준월**과 **인쇄**가 나온다. 모든 숫자는 **기준월 말일 기준**.
- **처리계획**은 여기서도 쓸 수 있고, 저장하면 팀 전체에 반영된다.
- 현장 화면 탭 — 종합 · 장기미처리 · 공가 · 상세 현황.

### 민원 현황 (세대 레벨)

업로드한 원본의 접수건을 세대(동·호) 단위로 묶어 **양호 · 주의 · 경계 · 심각 · 긴급** 다섯 단계로 나눕니다. AI 가 아니라 규칙입니다 — 매달 같은 기준, 근거를 댈 수 있습니다.

| 어디서 | 무엇을 |
|---|---|
| 대시보드 「현장별 민원 현황」 | 현장 × 레벨 히트맵(셀 농도 = 세대 수). 셀을 누르면 그 세대 목록, 현장명을 누르면 현장으로 |
| 현장 페이지 「민원 현황」 탭 | 민원 세대 현황(전월/금월 막대) + 동별 세대 현황도(층×라인 격자, 칸 색 = 레벨, 칸을 누르면 아래 표 검색) · 세대 표(레벨 탭, 하자유형·감지요소 칩 필터, 검색, 표시 건수, 머리 클릭 정렬, 머리 우클릭으로 필터 줄(`;` 로 OR)) · 행을 누르면 근거 접수건 |

- **판정 재료**: 접수내용의 고객 발화(직원 처리메모 제외, 쉼표로 섞인 문장은 나눠 봄)에서 감지요소 10종 — ★중대 4(안전위험 · 보상요구 · 법적·외부확산 · 감정격화·위협표현) · 일반 4(반복하자·반복민원 · 응대·소통불만 · 생활불편 · 책임·형평성불만) · 참고 2(처리지연·장기방치 · 사설시공·인테리어). 키워드가 있어도 민원 방향의 문맥이 있어야 잡습니다(「책임지고 처리」「사고 없이 마무리」는 무효). 접수 데이터로도 붙습니다 — 현재 미처리 지연 60일+ → 처리지연·장기방치, 세대 접수 8건+(또는 5건+·미처리 2건+)·같은 공간·유형 반복·재촉 날짜 2개+행동어 → 반복하자·반복민원. 세대 레벨화는 하자구분이 「세대」인 접수만 다룹니다(공용부 제외). 하자유형의 물리 심각도는 별도 축.
- **레벨**: 긴급 = ★중대 3개 이상, 또는 법적·외부확산이 있고 미처리가 남았으며 점수 7 이상 · 심각 = ★중대 1~2개 또는 일반 3개 이상 · 경계 = 일반 1~2개 또는 물리 심각(누수·균열·파손…) · 주의 = 참고 요소만 또는 물리 경계 · 양호 = 나머지. 1년 이상 방치는 한 단계 위(심각까지).
- **점수**(표의 「점수」 열, 등급 안 정렬): ★중대 +3 · 일반 +1 · 참고 +1 · 180일+ +1 · 365일+ +2 · 물리 심각 +2 · 물리 경계 +1(상한 12).
- 소송 미참여 세대 태그는 민원이 아닙니다(채권양도 안 한 세대 구분). 안내방송·화장대 오타·"자재발주"의 "재발" 같은 오탐은 제외 규칙에 있습니다.
- 규칙은 `app.js` 의 `RISK_RULES` 한 곳. 고치면 `node scripts/test/risk-gold.mjs`(예문 60건 정답셋 + 문맥 28건 + 점수·등급)가 회귀를 잡습니다. 실데이터 오탐 점검은 브라우저 콘솔에서 `riskAuditCSV('현장id')` — 접수번호·요소·검출어·판정·사유 CSV.
- 계산은 업로드 시 현장별로 되고 게시본에 함께 실리므로 마스터 PC 가 아니어도 팀 전원이 봅니다.

### 업무 색 — 그라디언트 줄

색 팝오버는 두 부분이다. 위는 **단색**(기본색 + 최근 쓴 색 + 직접 고르기), 아래 구분선 밑은 **그라디언트** 줄이다.

그라디언트는 **두 줄**이다. 위가 고정, 아래가 흐름(칩에 **▶**)이고 같은 순서라 세로로 짝이 맞는다.

| 줄 | 칩 | 색 이름 |
|---|---|---|
| 고정 | 무지개 + 색 7종 | `rainbow` · `grad-rd` `grad-og` `grad-yl` `grad-gr` `grad-bl` `grad-nv` `grad-pp` |
| 흐름 ▶ | 같은 8종 | 위 이름 뒤에 `-anim` (`rainbow-anim` · `grad-rd-anim` …) |

- 고정은 막대 폭에 맞춰 색이 **다 보이고**, 흐름은 8초 주기로 흐른다.
- 색 7종은 단색의 명암 차가 아니라 **이웃 색을 섞은** 그라디언트다(예: 빨강은 로즈–레드–오렌지).
  각 그라디언트는 시작 색으로 되돌아와 닫히므로 흐를 때 이음매가 보이지 않는다.
- 그리기와 흐름은 막대가 아니라 **`::after` 한 겹**이 맡는다. 흐름은 `transform` 을 미는 합성 애니메이션이라
  주 스레드를 쓰지 않는다(683차). 프레임은 `steps(160)`, 초당 20칸이다.
- 흐름은 사용자가 직접 고른 장식이므로 OS 「동작 줄이기」로 끄지 않는다 — 그 설정을 쓰는 사람의 선택지는 고정 쪽이다.

## 6. 조직 · 권한

> 팀·권역·현장의 기준 정보는 **조직 관리**에서 관리한다.

담당 범위는 **조직 관리**에서 정한다. 직급에 따라 쓰는 칸이 다르다.

| 직급 | 권역 | 담당 현장 | 보는 범위 |
|---|---|---|---|
| 팀장 · 안전 · 원가 | 비움 | 비움 | 팀 전체 |
| 공구장 | 지정 | 비움 | 그 권역 |
| 담당자 | 지정 | 지정 | 그 현장 |

- 담당 현장은 <svg width="15" height="15" viewBox="0 0 24 24" fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round" style="display:inline;vertical-align:-3px"><path d="M5 12h14"/><path d="M12 5v14"/></svg> 로 고르고, **칩을 누르면 빠진다**.
- 계정 탭 맨 끝 **미배정** — 새로 가입한 사람을 여기서 배정한다.
- **차단** 탭 — 차단한 계정만 모아 본다. 그 자리에서 권한을 되돌릴 수 있다.
- 팀장·공구장 지정은 관리자이거나 이미 팀장·공구장인 사람만 한다.

### 현장 표 토글

| 토글 | 켜짐 | 꺼짐 |
|---|---|---|
| **인수인계** | 인수를 받은 현장 — 하자 대시보드에 집계된다 | **인수 전 현장** — 권역은 그대로 두고, 하자처리 현황 사이드바에서 「인수 전 현장」 묶음에 들며 대시보드 집계에서 빠진다. 새 현장은 꺼진 채로 만들어진다 |
| **하자현황** | 하자 관리 화면에 보인다 | 하자 관리 화면에서 숨는다(현장·업무는 그대로) |
| 공가세대 · 공가상가 · 소제기 | 그 현장 하자 화면의 탭·표시 | — |

준공일 칸은 글자 칸이라 복사·붙이기가 된다 — `2026-07-04` · `2026.07.04` · `20260704` 어느 꼴이든 `YYYY-MM-DD` 로 맞춘다.

> 예전에는 권역 이름을 「인수 전 현장」으로 두어 갈랐다. 그 권역에 남은 현장도 그대로 인수 전으로 본다 — 권역을 실제 권역으로 바꾸고 인수인계 토글로 옮기면 된다.

### 권한

| 역할 | 업무 작성 | 조직 관리 · 설정 |
|---|---|---|
| **editor** (관리자) | O | O |
| **viewer** (사용자) | O | X |
| **blocked** | 로그인 차단 | — |

차단한 계정은 **차단 탭**으로 빠지며, 그 자리에서 되돌릴 수 있다. DB 규칙에서도 `org` · `people` · `cfg` 쓰기를 editor 로 제한한다.

**내 계정** — 사이드바 하단에서 이름 · 아바타 · 비밀번호 변경 · 로그아웃.

## 7. 바탕화면 위젯

반투명 창으로 달력을 띄운다. 날짜를 누르면 **앱과 똑같은 업무 패널**이 옆에 뜬다.
헤더의 **내 업무**에서 공통·미완료·보류를 모아 보고 바로 완료 처리한다.

### 알림

- **오늘 업무** — 컴퓨터를 켠 뒤 **하루 한 번**. 할 일이 없으면 뜨지 않는다.
- **오후 5시 이후** — 「오늘 남은 업무 N건」 말풍선.
- 끄기 — 위젯 설정(톱니) > 알림. 이 PC 에만 저장된다.

### 트레이 메뉴

보이기/숨기기 · 항상 위 · 자동 실행 · 업데이트 · 백업 · 진단 폴더 · 위치 초기화.
창 이동·크기는 평소 잠겨 있다. 설정 > **위치·크기 조정**을 켠 동안만 바꾼다.

## 10. 문제 해결

저장·조회에 실패하면 화면 아래에 원인이 표시됩니다.

- **저장 권한이 없습니다** — 계정 역할 또는 Firebase Rules 반영 상태를 확인합니다.
- **저장하지 못했습니다** — 네트워크 또는 Firebase 연결을 확인합니다. 잠시 후 서버 값으로 화면이 맞춰질 수 있습니다.
- 같은 오류가 짧은 시간에 반복되어도 같은 안내가 화면을 도배하지 않도록 묶어서 표시합니다.


| 증상 | 조치 |
|---|---|
| 저장이 안 됨 | 관리자에게 계정 권한 확인 요청 |
| 위젯이 안 뜸 | `문서\H 주요업무현황\HPlanWidgetLite.exe` 실행 |
| 화면이 옛 모습 | `Ctrl+Shift+R` |
| 원인을 알릴 때 | 설정 > 백업·기록 > **복사** → 관리자에게 전달 |

## 11. 시스템 개요

> 여기서부터(11~13)는 **시스템을 구축·배포하는 사람**을 위한 내용이다.

```
브라우저 / 위젯 / 휴대전화
        ↓
GitHub Pages  ← 정적 파일
        ↓
Firebase RTDB ← 데이터 · 인증 · 보안 규칙
```

서버가 없다. 정적 파일을 GitHub Pages 가 배포하고, 브라우저가 Firebase 와 직접 주고받는다.
**따라서 보안은 전부 DB 규칙(`database.rules.json`)에 달려 있다.**

### 파일

```
index.html                     화면·스타일 (CSS 전부 포함)
app.js                         모든 로직
database.rules.json            RTDB 보안 규칙 — 필드 추가 시 반드시 함께 수정
build-single.mjs               단일 HTML 빌드
vendor/                        FullCalendar · Chart.js · xlsx · Firebase SDK · Pretendard (자체 호스팅)
vendor/libredwg/               DWG 읽기 엔진(GNU LibreDWG → WebAssembly, GPL-3.0) + 전용 워커 dwg-worker.js
                               ⚠ 용량이 10MB 다. 배포에서 빠지면 「도면 인쇄」가 파일을 못 연다
scripts/test/static-audit.mjs  배포 전 정적 검사
scripts/test/smoke.mjs         브라우저 스모크
widget-lite/                   바탕화면 위젯 (Tauri · WebView2)
```

### 실행 모드

| 주소 | 모드 |
|---|---|
| 기본 | 로그인 + Firebase |
| `?local=1` | 계정 없이 이 브라우저에만 저장 (시연용) |
| `?w=1` | 위젯 레이아웃 — 달력만 |
| `?w=1&glass=1` | 위 + 반투명. **위젯이 실제로 여는 주소** |

`glass` 를 나눈 이유 — 위젯 창은 배경이 투명해 반투명으로 칠해야 바탕화면이 비친다.
브라우저로 `?w=1` 만 열 때(개발자 도구로 볼 때)는 뒤가 흰 페이지라 불투명이 맞다.

## 12. Firebase 세팅

### 1. 프로젝트

1. [Firebase 콘솔](https://console.firebase.google.com) > 프로젝트 추가
2. **Realtime Database** 생성 — 위치 `asia-southeast1`, **잠금 모드**
3. **Authentication** > 이메일/비밀번호 사용 설정
4. 설정 > 웹 앱 추가 → `firebaseConfig` 를 `app.js` 의 `FB.cfg` 에 넣는다

### 2. 보안 규칙

Realtime Database > 규칙에 `database.rules.json` **전체를 붙여넣는다.**

> ⚠ 건너뛰면 **누구나 데이터를 읽고 쓴다.** 서버가 없으므로 규칙이 곧 서버다.

### 3. 최초 관리자

가입은 앱에서, **첫 관리자만 콘솔에서** 올린다.

1. 앱에서 가입 → `users/{uid}` 가 `viewer` 로 생성됨
2. 콘솔에서 `users/{uid}/role` 을 **`editor`** 로 변경

이후에는 조직 관리 화면에서 바꾼다.

### 데이터 구조

| 경로 | 내용 |
|---|---|
| `calapp/tasks/{sid}/{iid}` | **업무 하나** — 일정과 업무가 통합된 단일 엔티티 |
| `calapp/org` | 팀·권역·현장 — 조직 관리의 기준 정보 |
| `calapp/people/{uid}` | 담당자 배정 |
| `calapp/offdays/{날짜}` | 팀 휴무일 |
| `calapp/cfg` | 앱 설정 |
| `calapp/prefs/{uid}` | 개인 설정 — 본인만 쓰기 |
| `calapp/trash/{sid}/{iid}` | 휴지통 — 30일 보관 |
| `calapp/archive/{sid}/{iid}` | 보관함 — 완료 6개월 뒤 |
| `users/{uid}` | 계정·권한 |
| `report/{YYYY-MM}` | 하자 월별 게시본 — 대시보드·현장 집계·미처리 목록 |
| `reportIndex/{YYYY-MM}` | 게시된 기준월 인덱스 |
| `plans/{sid}` | 현장별 처리계획 |
| `siteConfig/{sid}` | 현장별 하자 표시 설정 |

`sid` 는 업무가 담긴 자리다 — 첫 담당자의 uid, 없으면 팀 id.
⚠ **집계는 항상 `assignees` 로 한다. `sid` 에 기대지 않는다.**

캘린더와 업무 현황은 같은 업무를 다른 각도로 보여 준다. 항목 단위로 쓰므로 동시 작성해도 덮어쓰지 않고,
입력 중에는 실시간 수신 렌더를 보류해 타이핑이 지워지지 않는다.

팀·권역·현장은 `calapp/org`가 기준 정보이며, 하자 게시본의 `sites`·`teams`는 게시 시점의 집계용 스냅샷으로 저장한다.

## 13. 배포

### 최초 1회

1. 저장소 > Settings > Pages > **Deploy from a branch** > `main` / `(root)`
2. Firebase > Authentication > **승인된 도메인**에 배포 주소 추가

### 배포할 때마다

```bash
npm test                              # 전체 회귀 게이트
# 또는 개별 실행
node scripts/test/static-audit.mjs   # FAIL 0 · WARN 0 이어야 함
node scripts/test/risk-gold.mjs      # 민원 세대 레벨화 정답셋(60건)
node scripts/test/mobile-fit.mjs     # 폰 폭 겹침·잘림 + 데스크톱 가로 스크롤
node scripts/test/smoke.mjs          # 핵심 흐름 클릭 (CHROMIUM 환경변수 필요)
```

**버전 세 곳을 같은 숫자로 올린다.**

| 고칠 파일 | 고칠 자리 |
|---|---|
| zip 이름 | `calapp-v900` |
| `index.html` | `app.js?v=900` |
| `app.js` | `const APP_VER='900'` |

> 어긋나면 static-audit 이 FAIL 로 잡는다.

push 하면 GitHub Pages 가 자동 배포한다.
⚠ 규칙을 바꿨다면 **먼저** Firebase 콘솔에 붙여넣는다.

```bash
node build-single.mjs    # dist/ — 단일 파일 배포용
```

### 위젯 배포

> exe 빌드에 **개발 도구가 필요 없다.** 깃허브가 만든다.
> (팀원 PC 에는 최초 1회 설치. 이후 갱신은 자동.)

1. `widget-lite/Cargo.toml` 과 `tauri.conf.json` 의 `version` 을 같은 값으로 올려 push
2. 5~10분 뒤 **Releases** 에 `HPlanWidgetLite.exe` 가 올라온다
3. 팀원 위젯이 6시간마다 확인해 받아 두고, **다음 부팅 때 갈아탄다**

앱(index.html·app.js)만 고쳤다면 exe 를 다시 만들 필요가 없다 — 위젯은 배포된 주소를 불러온다.
`widget-lite/src/main.rs` 를 고쳤을 때만 다시 만든다.
