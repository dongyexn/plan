# H · 주요업무현황

팀 업무 일정 달력과 담당자별 업무 목록을 실시간으로 공유하는 사내 웹앱.
GitHub Pages + Firebase Realtime Database(무료 티어)로 동작한다.
배포 주소는 `https://dongyexn.github.io/plan/` (하자처리현황은 `/report/`).

이 문서는 **앱 안에서도 그대로 읽힙니다** — 상단바의 **?** 를 누르면 이 README 를 장별로 보여 줍니다.
⚠ 기능을 고치면 이 문서도 함께 고쳐야 합니다. 안내와 실제가 어긋나면 없느니만 못합니다.

## 시작하기

1. 회사 메일(@hdec.co.kr)로 로그인합니다.
2. 관리자가 **팀과 담당 현장**을 지정해 주면 내 업무가 보입니다.
3. 설정 > **바탕화면 위젯**에서 위젯을 내려받아 실행합니다. 이후에는 브라우저를 열지 않아도 됩니다.

> 위젯이 곧 이 앱입니다. 달력·오늘 업무·내 업무·알림이 모두 위젯 안에 있습니다.

### 문제가 생기면

- **저장이 안 될 때** — 대개 권한 문제입니다. 관리자에게 계정 권한을 확인해 달라고 하세요.
- **위젯이 안 뜰 때** — `문서\H 주요업무현황\HPlanWidgetLite.exe` 를 두 번 누르세요.
  그래도 안 되면 브라우저로 열어도 모든 기능을 쓸 수 있습니다.
- **원인을 알리고 싶을 때** — 설정 > **백업 · 기록** 의 **복사** 를 눌러 관리자에게 전달하세요.
  위젯 문제라면 트레이 > **진단 폴더 열기** > `widget-log.txt` 를 보내 주세요.

## 업무 다루기

### 업무 일정

달력에서 **날짜를 누르면** 오른쪽에 그날 업무가 나옵니다. 날짜를 끌면 기간이 잡히고, 그 상태에서 **업무 추가**를 누르면 기간이 그대로 들어갑니다.

- 카드 왼쪽 **색 원**은 담당자 색입니다. 프로필에서 색을 고르면 업무 막대도 그 색으로 나옵니다.
- 제목 오른쪽 **동그란 아이콘**을 누르면 진행 ↔ 완료가 바뀝니다.
- **팀 공통 업무는 기한이 지나면 저절로 완료**로 보입니다. 아직 진행 중이면 손으로 '진행'을 고르면 그대로 남습니다.
- **담당자 업무는 저절로 완료되지 않습니다.** 그날 처음 열 때 **놓친 업무 확인** 창이 떠서, 업무마다
  왼쪽 아이콘(완료) · **오늘로 이동** · **보류** 중에서 고릅니다. 고르는 즉시 반영되고, 남겨 두면 다음 날 다시 묻습니다.
- **보류함**은 넘긴 업무가 모이는 곳입니다(회색 원 안 − 아이콘). 캘린더 화면 오른쪽 아래에 있고,
  **업무를 달력 날짜로 끌어다 놓으면 그 날짜로 되살아납니다.** 업무 목록 화면에서는 왼쪽 **보류함**을 눌러 전체를 모아 볼 수 있습니다.
- **찾기**는 상단바 오른쪽의 검색창(또는 `Ctrl+K`)에서 엽니다. 업무 제목·내용·코멘트를 한 번에 찾습니다.
- 업무를 만들면 **입력하는 동안 저절로 저장**됩니다. 저장 버튼이 없습니다.
- 저장하지 않고 그만두려면 폼 오른쪽 위의 **X** 를 누릅니다.

### 업무 목록

왼쪽에서 대상을 고르면 오른쪽에 그 업무가 나옵니다. **팀 전체** · **공통 업무** · **권역** · 개별 **담당자** 중에서 고릅니다.

- 카드를 누르면 펼쳐집니다. **진행경과**·**처리계획**을 그 자리에서 고치고, 아래에 코멘트를 남깁니다.
- 코멘트에 `@이름` 을 쓰면 그 사람에게 알림이 갑니다.
- 완료한 업무는 일주일이 지나면 목록에서 감춰집니다(지워지지는 않습니다).
- 왼쪽의 ⠿ 를 잡고 끌면 순서가 바뀝니다.

### 우클릭 · 휴무일

**달력의 날짜나 업무 카드를 우클릭**하면 그 자리에서 바로 처리할 수 있는 메뉴가 뜹니다.

| 우클릭한 곳 | 할 수 있는 일 |
|---|---|
| 달력 날짜 | 이 날짜에 업무 추가 · **휴무일 지정/해제**(관리자) |
| 업무 카드 | 완료 ↔ 진행 · 수정 · 제목 복사 · 삭제 |

**단체연차 같은 팀 휴무일**은 관리자가 달력에서 그 날짜를 우클릭 > **휴무일로 지정**하면 됩니다.
이름을 적으면(기본값 `단체연차`) **공휴일과 같은 색으로 칠해지고** 날짜 위에 그 이름이 붙습니다.
글자 색이 공휴일과 달라 구분됩니다. 해제도 같은 자리에서 합니다.

> 입력칸 안이나 글자를 고르고 있을 때는 브라우저 기본 메뉴가 그대로 뜹니다.

## 내 업무와 알림

**내 업무** 화면에는 앞으로 7일 내 일정, 미완료 업무, 받은 부름이 모입니다.
읽은 부름도 **흐리게 남아** 나중에 되짚을 수 있습니다.

상단바의 **종** 을 누르면 받은 부름이 뜹니다. 안 읽은 것이 있으면 빨간 점이 붙습니다.

### 알림이 뜨는 때

트레이에 상주하는 위젯이 윈도우 알림을 띄운다.

- **오늘 업무** — 컴퓨터를 켠 뒤 한 번. 완료된 것은 세지 않고, **할 일이 없으면 띄우지 않는다.**
  ⚠ **하루 한 번만** 뜬다 — 재부팅을 여러 번 해도 다시 뜨지 않는다.
- **부름(@이름)** — 새로 받은 것만. 이미 알린 것은 다시 띄우지 않는다.
- 알림을 누르면 위젯이 앞으로 나오며 그 날짜(부름이면 그 업무)가 열린다.
- 끄려면 위젯 설정 > **알림** 토글. 이 PC 에만 저장된다.

## 바탕화면 위젯

`widget-lite/` 폴더가 바탕화면 위젯이다(Tauri · 윈도우 내장 WebView2, exe 수 MB).
반투명·테두리 없는 창으로 **달력만** 띄우고, 날짜를 누르면 그 칸 옆에
**앱과 똑같은 업무 패널**(카드 · 수정 · 자동 저장)이 뜬다.
예전 Electron 판(70MB)은 폐기됐다 — 팀원 PC 에 남아 있어도 새 위젯이 알아서 걷어낸다.

> 앱 안의 **사용 안내**(상단바 `?`)는 이 문서와 같은 내용·차례로 되어 있다.
> ⚠ 기능을 고치면 **둘 다** 고칠 것 — 어긋나면 안내가 오히려 방해가 된다.

## 팀 · 권역 · 현장 · 권한

팀·권역·현장 목록은 **하자처리현황이 원본**입니다. 그쪽에서 바뀌면 이 앱도 곧바로 따라가므로 여기서는 고치지 않습니다.

누가 어느 권역·현장을 맡는지는 **조직/현장 관리**에서 정합니다. 직급에 따라 쓰는 칸이 다릅니다.

| 직급 | 권역 | 담당 현장 |
|---|---|---|
| 팀장 · 안전 · 원가 | 비움 | 비움 (팀 전체를 봄) |
| 공구장 | 지정 | 비움 (권역 전체를 봄) |
| 담당자 | 지정 | 지정 |

### 권한

`users/{uid}/role` 값을 하자처리 대시보드와 공유한다.

| 역할 | 업무 작성 | 조직 관리 · 설정 |
|---|---|---|
| editor(관리자) | O | O |
| viewer(사용자) | O | X (보기 전용 안내 표시) |
| blocked | 로그인 차단 | — |

최초 관리자 1명은 Firebase 콘솔에서 `users/{uid}/role`을 `editor`로 직접 지정한다.
이후에는 조직 관리 화면에서 관리자가 다른 계정의 권한을 바꿀 수 있다.
앱에서 막을 뿐 아니라 DB 규칙에서도 `calapp/org` · `people` · `cfg` 쓰기를 editor로 제한하고,
일정·업무 노드에는 길이·형식 검증을 건다.

### 로그인

사내 도메인(`@hdec.co.kr`) 계정만 가입·로그인할 수 있고, 가입 시 받은 인증메일의 링크를
눌러야 진입된다. 최초 로그인 시 `users/{uid}`에 본인을 `viewer`로 자기 등록한다.
사이드바 하단 계정 카드에서 이름 변경 · 비밀번호 변경 · 로그아웃을 할 수 있다.

주소 뒤에 `?local=1`을 붙이면 계정 없이 이 브라우저에만 저장되는 로컬 모드로 열린다(시연용).

## 백업

**위젯이 알아서 한다.** 관리자 계정으로 로그인해 위젯을 켜 두면, 주 1회
`문서\H 주요업무현황\backup\hplan_260801.json` 형식으로 저장한다. 최근 12개만 남기고 오래된 것부터 지운다.

- 담는 것: 업무 · 담당자 배정 · 설정. 마지막 저장 시각은 **설정 > 백업**에서 볼 수 있다.
- 바로 남기고 싶으면 트레이 > **지금 백업하기**.
- ⚠ **관리자 계정이고 자료를 다 받은 뒤에만** 저장한다 — 빈 파일로 덮어쓰지 않기 위해서다.
- 위젯을 쓰지 않는 관리자는 설정 > 백업 > **내보내기**로 내려받기 폴더에 저장할 수 있다.
- 되돌리기: 설정 > 백업 > **불러오기** 에서 파일을 고른다.
  ⚠ 팀·권역·현장은 하자처리 현황이 원본이라 되돌리지 않는다.

### 화면 구조

**주요 업무** — 주 단위 업무보고용 표.
보고 주기는 **목요일에 시작해 수요일에 끝난다**(8/6~8/12 → 8/13~8/19 …).
권역마다 카드가 하나씩 생기고, 그 안에 **완료**(이번 주기)와 **예정**(다음 주기)이 좌우로 놓인다.
열은 담당자 · 현장 · 업무 · 완료일(예정일) · 비고이고, 업무가 없는 담당자도 빈 줄로 남긴다.
팀 공통 업무 · 권역 미지정 · 인수 전 현장 권역은 보고 대상에서 뺀다.
완료일은 업무의 종료일(없으면 날짜)이고, 비고는 처리계획(없으면 진행경과)을 가져온다.
왼쪽 위 화살표로 주기를 옮기고, [인쇄 · PDF] 로 표만 뽑을 수 있다.

**조직/현장 관리(관리자)** — 사이드바에서 고른 팀을 기준으로 권역 · 현장 · 계정을 관리한다.
계정은 선택한 팀 소속과 팀 미배정만 보이고, 미배정 계정은 "이 팀에 추가"로 편입한다.
담당 현장은 + 버튼을 눌러 권역별 목록에서 고른다.

**설정** — 메일 발송, 다크 모드, 사용 안내, 버전 · 오류 기록 복사, 백업, **바탕화면 위젯** 다운로드.

### 데이터 (RTDB `calapp/`)

| 경로 | 내용 |
|---|---|
| `calapp/tasks/{subjectId}/{itemId}` | **업무 하나** — 일정과 업무 목록이 통합된 단일 엔티티. text(제목)·prog(진행경과)·plan(처리계획)·site(현장)·st(0예정 1진행 2완료 3보류)·kind(업무 구분)·order·assignees·links·color·comments + date·end·time·recur·remind(달력에 뜨는 일정 성격) |
| `calapp/mentions/{uid}` | 코멘트에서 나를 부른 알림 |
| `calapp/org` | 팀 · 권역 · 현장 목록 |
| `calapp/people/{uid}` | 담당자 배정 — name·email·team·region·sites |
| `calapp/cfg` | 앱 설정 — 주간 메일 켬/끔(mail/weeklyOn) |
| `calapp/prefs/{uid}` | 개인 설정 — 본인만 쓰기 |
| `users/{uid}` | 계정·권한·프로필(avColor·avIcon) — 하자처리 대시보드와 **공용** |

업무 일정과 업무 목록은 **같은 업무를 다른 각도로 보여준다** — 날짜가 있으면 달력에 뜨고,
담당자·상태가 있으면 업무 목록에 뜬다. 두 화면의 카드·폼·자동 저장은 같은 코드를 쓴다.
예전 구조(plans·recur 분리)로 저장된 데이터는 앱을 열 때 자동으로 업무로 옮겨진다.

항목 단위로 쓰기 때문에 여러 명이 동시에 작성해도 서로 덮어쓰지 않는다.
입력 중에는 실시간 수신 렌더를 보류해 타이핑이 지워지지 않는다.

### 배포 절차

0. **배포 전 검증**: `node scripts/test/static-audit.mjs` — 의존성 없이 바로 돈다.
   죽은 함수 · 짝 잃은 `data-act` · 죽은 CSS · 규칙-저장 필드 불일치 · 외부 CDN 재유입 ·
   버전 쿼리 태그 훼손 · 단일 빌드 동작을 검사한다(FAIL 있으면 종료 코드 1).
   브라우저 스모크는 `scripts/test/smoke.mjs`(puppeteer 필요 — 회사망은 npm 이 막히므로 집 PC에서).
1. 새 저장소에 폴더 전체를 push → Settings > Pages → 배포.
   (단일 파일로 올리려면 `node build-single.mjs` 후 `dist` 내용만 올린다.)
2. Firebase 콘솔 > Realtime Database > 규칙에 `database.rules.json` **전체를 붙여넣기**.
3. 저장소 Settings > Secrets and variables > Actions에 등록(메일 발송용):
   - `FIREBASE_SERVICE_ACCOUNT` — Firebase 콘솔 > 프로젝트 설정 > 서비스 계정 > 새 비공개 키(JSON 전체)
   - `BREVO_API_KEY` — brevo.com(무료 300통/일) > SMTP & API > API Keys
   - `MAIL_FROM` — Brevo에서 인증한 발신 주소
5. 메일 테스트: Actions 탭 > 워크플로 > Run workflow(수동 실행).

```
node build-single.mjs      # dist/index.html + dist/vendor/
```

index.html과 app.js를 한 파일로 합친다. 인라인 스크립트를 쓰면서도 CSP를 유지하려고
스크립트 본문의 SHA-256 해시를 계산해 `script-src`에 넣고, 산출물에서 다시 검증한다.

#### 배포용 exe 만들기 — 깃허브가 만든다

**회사 PC 에 아무것도 깔 필요 없다.** 브라우저만 있으면 된다.

1. `widget-lite/Cargo.toml` 의 `version` 을 올려 올린다(깃허브 웹의 연필 아이콘으로 고쳐도 된다).
   → 그 폴더의 파일이 올라오면 빌드가 자동으로 시작된다. (직접 돌리려면 Actions > Run workflow)
   ⚠ `tauri.conf.json` 의 `"version"` 도 같은 값으로 맞춘다.
2. 5~10분 뒤 **Releases** 에 태그 `widget-lite-v버전` 으로 `HPlanWidgetLite.exe` 가 올라온다.
3. **끝.** 위젯이 릴리스 주소에서 최신 버전을 스스로 확인해 받아 둔다.

설정 파일은 `.github/workflows/widget-lite.yml` 하나뿐이고, 손댈 일은 없다.
소스만 고쳐 올려도 빌드는 돌지만, **같은 버전의 릴리스가 이미 있으면 건너뛴다** — 배포하려면 버전을 올린다.

앱을 고쳤을 때는 exe 를 다시 만들 필요가 없다 — 위젯은 배포된 웹 주소를 불러오므로 새로고침만으로 반영된다.
(위젯 자체 코드인 `widget-lite/src/main.rs` 를 고쳤을 때만 다시 만든다.)

#### 트레이 메뉴

| 항목 | 설명 |
|---|---|
| 위젯 보이기 / 숨기기 | 트레이 아이콘 클릭도 같은 동작 |
| 항상 위에 표시 | 끄면 **바탕화면 모드**(기본) — 반투명·입력 가능·다른 창에 가려짐 |
| 윈도우 시작 시 자동 실행 | 마지막 위치·크기 그대로 다시 뜬다 |
| 업데이트 확인 / 지금 업데이트 | 받아 둔 새 버전이 있으면 '지금 업데이트'로 바뀐다 |
| 새로고침 / 개발자 도구 | 화면이 이상할 때 |
| 지금 백업하기 / 진단 폴더 열기 | 백업·오류 기록이 있는 문서 폴더를 연다 |
| 위치·크기 초기화 | 창이 화면 밖으로 나갔을 때의 탈출구 — 주 모니터 오른쪽 위로 되돌린다 |
| 자동 실행 상태 확인 / 브라우저 앱 열기 / 종료 | |

위젯은 처음 실행될 때 자기 자신을 **`문서\H 주요업무현황\HPlanWidgetLite.exe`** 로 복사하고,
자동 실행도 그 자리로 등록한다. 다운로드 폴더에 두고 잊어버려도 다음 부팅부터는 이 자리에서 뜬다.
부팅마다 **예전 Electron 판의 흔적**(구 exe·구 자동 실행 등록)을 스스로 걷어낸다 —
팀원 PC 에서 손으로 지울 것이 없다.

#### 위젯 업데이트 (팀원은 아무것도 안 해도 된다)

1. `widget-lite/Cargo.toml`(과 `tauri.conf.json`)의 `version` 을 올려 올린다 — 깃허브가 exe 를 만들어 릴리스에 올린다.

팀원 위젯은 시작 뒤 한 번, 그다음 6시간마다 릴리스를 확인해 **새 파일을 미리 받아 둔다.**
받아 둔 뒤에는 **다음에 컴퓨터를 켤 때 저절로 갈아탄다**(PC 카카오톡과 같은 방식).
기다리지 않고 바로 적용하려면 트레이의 **'지금 업데이트 (v…)'** 를 누르면 된다(되묻는 창이 뜬다).

동작 방식과 안전장치
- 실행 중인 exe 는 스스로 덮어쓸 수 없다 → **창을 만들기 전에** 현재 파일을 `.old` 로 밀어내고 새 파일을 제자리에 놓는다.
- 받다 만 파일로 바꿔치면 위젯이 아예 안 뜨므로, **크기를 확인한 뒤에만** 정식 이름을 준다.
- 교체에 실패하면 원래 파일을 되돌리고 **그냥 지금 버전으로 뜬다**(다음 기회에 다시 시도).
- 버전이 지금 것보다 높을 때만 갈아탄다 — 잘못 적힌 값으로 매 부팅 교체가 반복되지 않는다.
- 다운로드 폴더 등 **다른 자리에서 실행하면 문서 폴더의 파일로 넘겨주고 종료**한다(두 벌이 돌아다니지 않게).

⚠ **바탕화면 아이콘이 달력 위에 보이게 하는 '벽지 층 부착' 모드는 뺐다.**
아이콘이 위로 오려면 창이 벽지 창의 자식(`WS_CHILD`)이어야 하는데, 자식 창은
키보드 포커스와 반투명(레이어드)을 둘 다 잃어 위젯으로 쓸 수 없다.

창 이동·크기 변경은 평소 잠겨 있다. 위젯 설정(톱니) > **위치·크기 조정** 을 켠 동안만 바꾸고,
끝내면 그 위치·크기가 저장되어 다음 실행에도 그대로 뜬다.
`widget-lite/src/main.rs` 상단 `app_url()` 이 위젯이 여는 주소다(기본 `.../plan/?w=1`).
바탕화면 모드는 user32 의 `SetWindowPos(HWND_BOTTOM)` 직접 호출로 창을 맨 아래 층에 유지한다.
